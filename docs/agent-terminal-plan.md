# 에이전트 터미널 연동 및 기존 플러그인 공존 계획

> 과거 계획 기록입니다. Java 21·IDE 2024.2 호환 정책은 폐기했습니다. 현재 기준은 Java 25와 IntelliJ IDEA 2026.2.4이며, 최신 실행·검증 절차는 [development.md](development.md)를 따릅니다.

## 1. 목표와 범위

SnakeOrCamel에 여러 에이전트 실행 명령을 프로필로 저장하고 IDE Terminal 도구창에서 실행하는 기능을 추가한다. **참조 삽입 단축키 ⌥⌘K는 항상 화면에 표시된 Terminal 도구창의 첫 번째 탭을 대상으로 한다.** 현재 활성 탭이나 기본 프로필은 대상 탭 선택을 바꾸지 않는다.

편집기에 선택 영역이 있으면 파일·라인 범위, 없으면 파일 전체 참조를 에이전트 질문 입력창에 삽입한다. 질문 입력창이 준비될 때까지 참조를 보관했다가 자동으로 한 번 삽입하며, 참조 삽입에는 줄바꿈이나 Enter를 보내지 않는다.

새 기능은 기본 비활성화하고 사용자가 동작 안내와 충돌 정보를 확인한 뒤 활성화한다. 기존 이름 변환과 JSON Prettier는 계속 제공한다. 지원·검증 대상은 IntelliJ IDEA Community 2024.2와 IntelliJ IDEA 2026.2.4다. 다른 IntelliJ 기반 IDE의 호환성은 별도로 검증한다.

이 문서는 후속 기능 구현을 위한 계획이다. 이번 산출물은 `docs/agent-terminal-plan.md`이며, 아래 기능 구현이나 CLI·샌드박스 검증이 완료되었음을 의미하지 않는다. Diff 표시, 진단 공유, 선택 영역 상시 공유는 구현 범위에서 제외한다.

## 2. 참고 자료와 설계 구분

- [Claude Code 공식 JetBrains 안내](https://code.claude.com/docs/en/jetbrains)는 실행·파일 참조 전달 흐름을 참고한다. 공식 연동의 자동 선택 컨텍스트 공유와 이 계획의 명시적 참조 삽입은 별도 기능이다.
- [Codex CLI 예시 플러그인](https://github.com/olehkhomyk/codex-terminal)은 프로필 명령 실행과 편집기 참조 전달 흐름을 참고한다. 이 플러그인의 코드나 설정에 의존하지 않는다.
- [Codex 액션 설정](https://github.com/olehkhomyk/codex-terminal/blob/main/src/main/resources/META-INF/plugin.xml)에는 `com.github.codexjb`와 `Codex.InsertRef`, macOS `meta alt K` 및 기본 Keymap의 `ctrl alt K` 배정이 명시되어 있다. Claude 공식 안내에도 같은 참조 단축키가 있으므로 설치 여부만으로 충돌을 판단하지 않는다.
- [JetBrains Embedded Terminal API 안내](https://plugins.jetbrains.com/docs/intellij/embedded-terminal.html)에 따라 터미널 엔진별 어댑터를 분리한다. 안내상 Reworked Terminal API는 2025.3부터 제공되며 experimental 상태다. API 존재만으로 두 IDE에서의 동작이 검증된 것으로 간주하지 않는다.

첫 번째 탭 고정, 기본 OFF, 실행 준비 판정, 중복 예약 방지와 아래 복구 정책은 SnakeOrCamel의 요구사항이다. 참고 플러그인이 같은 정책을 제공한다고 가정하지 않는다.

## 3. 기본 비활성화와 활성화 절차

설정 위치는 `Settings → Tools → SnakeOrCamel → Agent Terminal`로 한다.

- 최초 설치 및 이 기능이 없는 버전에서의 업데이트 시 활성화 기본값은 OFF다. 사용자가 이후 명시적으로 켠 값은 재시작과 후속 업데이트에서도 보존한다.
- OFF에서는 에이전트 실행 명령 전달, 참조 자동 삽입, 터미널 감시, 새 단축키 연결을 수행하지 않는다. 설정 화면의 상태 조회는 터미널 감시와 분리한다.
- 활성화 전에 첫 번째 탭 규칙, 명시적 실행 요청 시의 자동 실행·삽입, Enter 미전송, 현재 단축키 충돌 정보를 표시한다.
- 활성화 여부는 IDE 사용자 설정에 저장한다. 프로젝트 설정이 활성화를 유발하지 않도록 한다.
- 실행 프로필은 프로젝트 로컬 설정에 저장한다. 명령·로컬 경로가 버전 관리나 Settings Sync로 자동 공유되지 않도록 저장 범위를 정한다.
- 기능 활성화, IDE 재시작 또는 프로젝트 열기만으로 에이전트를 실행하지 않는다. 실행은 사용자의 `Run Agent…` 또는 참조 삽입 요청에서만 시작한다.
- OFF에서 액션이 호출되면 터미널에 접근하지 않고 설정 안내를 제공한다. Terminal 플러그인이 없거나 비활성 상태이면 기능을 사용할 수 없음을 설정에 표시한다.

설정 화면에는 기존 플러그인의 설치 여부와 활성 상태를 각각 표시한다.

| 플러그인 | 플러그인 ID |
|---|---|
| Claude Code | `com.anthropic.code.plugin` |
| Codex CLI 예시 플러그인 | `com.github.codexjb` |

설치됐지만 비활성화된 상태도 구분한다. 두 플러그인은 선택적 공존 대상이며 SnakeOrCamel의 의존성으로 추가하지 않는다. 기존 플러그인의 자동 컨텍스트 공유와 SnakeOrCamel의 참조 삽입이 함께 동작할 수 있음을 안내한다.

## 4. 단축키 충돌과 소유권

새 액션 ID는 다음으로 고정한다.

| 액션 | ID | 노출 위치 |
|---|---|---|
| 프로필 선택·실행 | `SnakeOrCamel.AgentTerminal.Run` | Tools → SnakeOrCamel → Run Agent… |
| 현재 파일·선택 참조 삽입 | `SnakeOrCamel.AgentTerminal.InsertReference` | Tools 메뉴, 편집기 우클릭 메뉴 |

참조 단축키는 macOS `alt meta K`(⌥⌘K), Windows/Linux `control alt K`다. `plugin.xml`에 무조건 적용되는 기본 단축키를 선언하지 않는다. 액션 등록과 실제 키 연결을 분리해 OFF 상태에서 기존 배정에 영향을 주지 않는다.

1. 사용자가 활성화하면 현재 Keymap의 실제 배정을 검사한다. 두 공존 플러그인 외의 모든 액션과 사용자 지정 배정도 확인한다. 다중 키 단축키의 시작 키 충돌도 검사한다.
2. 충돌이 없으면 SnakeOrCamel 참조 액션에 연결한다. 읽기 전용 Keymap 등으로 연결할 수 없으면 Keymap 설정을 안내한다.
3. 충돌이 있으면 기존 배정을 유지한다. 충돌 액션 이름·ID와 Keymap 설정 진입 방법을 보여 주고 해당 키에 SnakeOrCamel 액션을 추가하지 않는다. 활성화된 기능은 메뉴로 사용할 수 있다.
4. 사용자가 충돌을 해소하고 다시 확인하면 연결한다. Keymap 전환·변경 시에도 현재 배정을 재검사하고 기존 액션을 삭제하거나 대체하지 않는다.
5. 비활성화하면 감시 작업을 취소하고 SnakeOrCamel이 자동으로 추가한 연결만 해제한다. 사용자가 직접 추가·수정한 Keymap 배정은 보존한다.

자동 연결은 Keymap 식별자, 액션, 키와 사용자 변경 여부를 추적한다. 종료·재시작 후에도 자동 연결과 사용자 배정을 구분하며, 구분할 수 없는 배정을 임의 삭제하지 않는다. 여러 프로젝트에서 열린 설정·세션이 같은 단축키를 중복 등록하지 않도록 연결 관리는 IDE 사용자 범위에서 처리한다. 비활성 상태에서는 사용자가 보존한 키로 액션을 호출해도 실행·삽입하지 않는다.

다른 플러그인의 단축키, 설정 또는 활성 상태는 자동 변경하지 않는다. 기존 `Name.Convert` 액션 ID와 단축키도 유지한다.

## 5. 실행 프로필

프로필은 프로젝트별로 다음 정보를 저장하며 추가·수정·삭제와 기본 프로필 선택을 제공한다.

| 항목 | 정책 |
|---|---|
| 식별자 | 이름 변경과 무관한 안정적인 ID로 자체 생성 탭을 연결 |
| 이름 | 프로필 선택 화면에 표시 |
| 종류 | `Claude`, `Codex`, `Custom` |
| 실행 명령 | 셸에서 실행할 원문 명령 |
| 작업 디렉터리 | 기본값은 프로젝트 루트, 명시 경로 지정 가능 |
| 준비 감지 패턴 | Custom에서 선택 설정; 없으면 수동 삽입 |

초기 예시는 `claude`, `codex`로 제공한다. 옵션과 기본 프로필은 사용자가 선택·편집한다. 기본 프로필이 없으면 첫 실행 요청에서 선택하게 하고 추측해 실행하지 않는다. 기존 플러그인의 실행 설정은 자동으로 가져오지 않는다.

명령은 IDE 터미널 셸에 사용자가 입력한 그대로 전달한다. 명령을 임의 분해하거나 옵션을 추가하지 않는다. 빈 명령, 유효하지 않은 작업 디렉터리는 실행 전에 알린다. 프로젝트 루트가 없으면 작업 디렉터리를 지정하게 한다.

`Run Agent…`는 프로필을 선택해 실행하고 SnakeOrCamel이 생성한 프로필별 탭을 ID로 찾아 재사용한다. 이름만 같은 외부 탭을 프로필 탭으로 취급하지 않는다. 재사용 탭에서 에이전트가 실행 중이면 포커스만 이동한다. 확인된 빈 셸에서만 다시 실행하고, 다른 프로그램·미전송 입력·상태 불명인 경우 기존 상태를 보존한다.

작업 디렉터리는 새 탭 생성 시 적용한다. 기존 탭의 실제 작업 디렉터리를 프로필 값으로 간주하거나 실행 중인 탭에 `cd`를 주입하지 않는다. 설정 변경을 이유로 실행 중인 프로세스를 종료·재시작하지 않는다.

실행 명령을 시작하기 위한 실행 신호와 질문 참조 삽입을 분리한다. 실행 명령은 명시적 요청에 따라 실행하지만 참조에는 Enter를 보내지 않는다.

## 6. 첫 번째 탭 선택과 기존 세션 재사용

참조 액션은 Terminal 도구창의 **화면상 탭 순서**로 첫 번째 탭을 결정한다. API가 반환하는 목록의 첫 원소나 최근 활성 탭을 그대로 선택하지 않는다. 분할 터미널은 기본 탭 그룹의 첫 번째 탭을 사용한다. 탭·세션 대응이나 분할 내 입력 대상을 확정할 수 없으면 다른 탭으로 우회하지 않고 안내·참조 보관 상태로 전환한다.

| 첫 번째 탭 상태 | 처리 |
|---|---|
| 탭 없음 | 첫 탭 생성 → 기본 프로필 실행 → 질문 입력창 준비 후 참조 삽입 |
| 셸 대기 중이고 미전송 입력 없음 | 기본 프로필 실행 → 질문 입력창 준비 후 참조 삽입 |
| Claude·Codex 질문 입력창 준비 완료 | 기존 질문을 유지하며 참조 삽입 → 해당 탭으로 포커스 이동 |
| 시작·로그인·신뢰 확인 중 | 참조 보관 → 질문 입력창 준비 확인 후 자동 삽입 |
| 다른 프로그램 실행 중·셸 입력 존재·상태 불명 | 기존 입력 유지 → 안내 및 참조 보관, 상태 확인 전에는 실행·삽입하지 않음 |

첫 번째 탭이 기존 Claude·Codex 플러그인에서 만든 탭이어도 같은 규칙으로 재사용한다. 탭 이름만으로 실행 중인 에이전트를 판단하지 않는다. 기본 프로필이 Codex여도 첫 번째 탭의 Claude가 준비되어 있으면 그 Claude에 맞춰 삽입한다.

실행 중인 에이전트를 중복 실행하거나 종료·재시작하지 않는다. 기존 플러그인의 실행 액션을 호출해 다른 탭으로 이동하지 않는다. 기존 IDE 연결, 환경 변수, 설정 파일을 변경하지 않는다.

요청 시 프로젝트·탭·세션 ID와 첫 번째 위치를 기록한다. 대기 중 대상 탭이 닫히거나 첫 번째 위치에서 이동하면 예약을 취소하고 재시도를 안내한다. 새 첫 번째 탭으로 예약을 옮기지 않는다. 자동 삽입 직전에도 대상과 위치, 세션·준비 상태를 다시 확인한다. 확인 후 전송 사이에 세션이 바뀐 경우에도 이전 요청을 재사용하지 않는다.

## 7. 파일·라인 참조 생성

| 편집기 상태 | 참조 예시 |
|---|---|
| 선택 없음 | `@src/Example.java` |
| 한 줄 선택 | `@src/Example.java#L12` |
| 여러 줄 선택 | `@src/Example.java#L12-L34` |

라인 번호는 1부터 시작한다. 선택 범위는 시작 포함·끝 제외로 계산한다. 선택 끝이 다음 줄 시작이면 끝 오프셋 직전 문자가 속한 줄까지만 포함한다. 빈 선택은 라인 범위를 만들지 않는다. 여러 선택 영역은 파일별로 겹치는 라인 범위를 합치고 파일·라인 순서로 삽입한다. 선택이 하나라도 있으면 선택 없는 캐럿 때문에 파일 전체 참조를 추가하지 않는다. 여러 참조는 줄바꿈 없이 공백으로 구분한다.

현재 파일의 미저장 변경은 전달 전에 저장한다. 대기 중 추가 편집이 있었다면 실제 삽입 직전에도 저장하고, 보관한 선택 위치는 문서 변경을 추적할 수 있는 범위로 관리한다. 파일 삭제, 범위 무효화 또는 저장 실패 시 자동 전송하지 않고 재시도를 안내한다. 디스크 파일이 없는 편집기는 안내하고 전달하지 않는다.

세션의 확인된 작업 디렉터리 내부 파일은 상대 경로, 외부 파일은 절대 경로를 사용한다. 기존 탭의 작업 디렉터리를 확인할 수 없으면 절대 경로를 사용한다. 프로필의 디렉터리를 기존 세션의 디렉터리로 대체하지 않는다. 경로 포함 여부는 문자열 접두어 비교가 아닌 정규화된 경로로 판단한다.

공백·한글 경로의 인용과 구분자는 CLI별 참조 포매터에서 처리한다. 셸 명령 인용법이 CLI 질문 입력창에서도 같다고 가정하지 않는다. 두 CLI에서 파일과 라인 범위가 실제 인식되는지 확인한 형식만 지원한다고 기록한다. 표현할 수 없는 경로는 무리하게 삽입하지 않고 참조 복사와 안내를 제공한다.

기존 질문과 커서 입력을 지우지 않으며, 필요한 공백 외에는 다른 텍스트·줄바꿈·제어 문자를 추가하지 않는다. 참조 전송 경로는 실행 명령 전송과 분리해 Enter 미전송을 검증한다.

## 8. 준비 감지·자동 삽입·복구

Claude·Codex별 질문 입력 화면 감지기를 제공한다. 현재 화면과 커서·입력 상태를 함께 검사하고 일반 출력 버퍼와 TUI 대체 화면 버퍼를 구분한다. 과거 출력에 남은 프롬프트나 탭 이름, 프로세스 존재, 고정 대기 시간만으로 준비 완료를 판단하지 않는다.

감지 상태는 최소한 `빈 셸`, `시작 중`, `사용자 확인 필요`, `질문 입력 준비`, `다른 프로그램`, `불명`으로 나눈다. 로그인·권한·신뢰 확인은 사용자에게 맡기고 응답을 자동 입력하지 않는다. 사용자가 확인을 마친 뒤 질문 입력창이 감지되면 남은 대기 시간 내에서 자동 삽입한다.

- 준비되면 보관한 참조를 한 번만 삽입한다. 전송 성공 후 예약을 제거하고 화면 이벤트가 반복되어도 재전송하지 않는다.
- 반복 단축키로 동일 프로젝트·대상 세션·파일·라인 참조를 중복 예약하지 않는다. 서로 다른 요청은 별도 보관하되 순서를 유지하고 동일 참조는 합친다.
- 각 요청은 접수 시점부터 최대 30초 동안 대기한다. 반복 단축키가 동일 요청의 제한 시간을 무한 연장하지 않게 한다.
- 30초 동안 준비를 확인하지 못하면 해당 요청의 자동 삽입을 중단한다. 재시도와 참조 복사를 제공하며, 이후 화면이 바뀌어도 만료된 요청을 자동 전송하지 않는다.
- 탭 종료·이동, 기능 비활성화, 프로젝트 종료 시 예약·리스너·타이머를 해제한다. 취소된 비동기 결과로 뒤늦게 삽입하지 않게 한다.
- 전송 결과가 불명확하면 자동 재전송하지 않는다. 중복 가능성을 알리고 사용자가 터미널 내용을 확인한 뒤 재시도하게 한다.
- Custom은 사용자가 준비 완료 감지 패턴을 설정한 경우에만 자동 삽입한다. 패턴 오류를 검증하고 로그인·권한 확인 화면에서는 삽입하지 않는다. 패턴이 없으면 사용자가 질문 입력창을 확인한 뒤 누르는 수동 삽입과 참조 복사를 제공한다.

다른 프로그램·셸 입력 존재·상태 불명일 때의 보관은 입력 허가를 의미하지 않는다. 지원되는 질문 입력창으로 안전하게 판정되지 않으면 복사·재시도만 제공한다. 참조 보관은 프로젝트 세션 메모리로 제한하며 IDE 재시작 후 자동 복원·삽입하지 않는다.

검증 시 CLI 버전, IDE 버전, 터미널 엔진, OS·셸, 준비 화면 표본, 경로 참조 인식 결과를 기록한다. 검증되지 않은 CLI 버전의 화면 변경으로 감지가 실패할 수 있음을 안내한다. 실제 검증 전에는 특정 버전이 지원된다고 기록하지 않는다.

## 9. 구현 구조와 호환성

`src/main/java/io/snakeorcamel/agentterminal/`에 다음 책임을 분리한다. 클래스명은 구현 시 확정하되 터미널 API 의존성이 참조 생성기와 설정으로 퍼지지 않도록 한다.

| 구성 | 책임 |
|---|---|
| IDE 사용자 설정·설정 화면 | 기본 OFF, 안내, 플러그인 상태, 활성화 처리 |
| Keymap 연결 관리자 | 현재 충돌 검사, 자동 연결 소유권, 해제·변경 추적 |
| 프로젝트 프로필 저장소 | 프로필 CRUD, 기본 프로필, 로컬 저장 |
| 실행·참조 액션 | 컨텍스트 수집, 활성화 확인, 사용자 요청 전달 |
| 참조 생성기·CLI 포매터 | 선택 범위 병합, 경로 계산, CLI별 참조 문자열 |
| 프로젝트 세션 관리자 | 자체 탭 매핑, 첫 탭 요청, 예약·만료·취소 |
| 터미널 어댑터 | 화면 순서, 탭 ID, 디렉터리, 화면 읽기, 입력·포커스 |
| 준비 감지기 | Claude·Codex·Custom 상태 판정, 검증 표본 처리 |

Terminal 플러그인 `org.jetbrains.plugins.terminal`은 선택 의존성으로 등록한다. 전용 선택 의존성 descriptor와 어댑터 로딩 경계를 두어 플러그인이 없거나 비활성 상태여도 기존 이름 변환·JSON 기능과 설정 진입이 로드된다. 메인 클래스의 정적 참조로 Terminal 전용 클래스가 강제 로드되지 않도록 한다.

| IDE·엔진 | 지원 방침 |
|---|---|
| 2024.2 Classic | 2024.2에서 제공되는 공개 API를 쓰는 Classic 어댑터 |
| 2024.2 실험적 엔진 | 입력을 시도하지 않고 Classic 전환 안내 |
| 2025.3 이상 Reworked | 신형 공개 API를 사용하는 별도 어댑터; 2026.2.4에서 실제 검증 |
| 지원 API·화면 순서 확인 불가 | 오류를 격리하고 지원 불가·재시도·복사 안내 |

컴파일 기준 2024.2와 단일 배포 ZIP을 유지한다. 신형 API는 어댑터 내부에서 공개 API에 대한 리플렉션으로만 연결한다. private 멤버·내부 API 접근이나 접근 제한 우회를 사용하지 않는다. API 탐색·호출 실패는 기존 기능으로 전파하지 않는다. 신형 API의 공개성·버전별 시그니처·화면상 탭 순서 대응을 구현 초기에 검증하며, 확보되지 않은 기능을 추측으로 대체하지 않는다.

UI 조작·편집기 스냅샷·문서 저장은 필요한 EDT 규칙을 따른다. 화면 감지·대기는 비동기로 수행하고 EDT에서 대기하거나 sleep하지 않는다. 세션별 취소 토큰·수명 관리를 두고 전송 직전 활성화·프로젝트·대상 상태를 재확인한다. 기능 비활성화는 열린 모든 프로젝트의 작업을 취소한다.

기존 공개 API·액션 ID·플러그인 ID와 버전 `1.1.0`을 유지한다. Java 25 빌드, 모든 Java 컴파일의 `--release 21`, Gradle 9.8.2, IntelliJ Platform Gradle Plugin 2.19.0, `sinceBuild 242` 및 현재 검증 실패 정책을 유지한다. 신형 API 연결을 위해 컴파일 기준이나 최소 지원 버전을 올리지 않는다.

단계 4의 API 조사에서 구현을 보장할 수 없는 지점은 결과와 제한을 기록한다. 준비 감지나 탭 대응이 미검증인 채 전체 기능 완료로 표시하지 않는다.

### 자동 검증

- 참조 생성: 선택 없음, 한 줄·여러 줄, 다음 줄 시작에서 끝나는 선택, 파일 끝·CRLF, 다중 선택·겹침·정렬·빈 캐럿, 외부 파일, 알 수 없는 작업 디렉터리, 공백·한글 경로.
- 상태·예약: 빈 셸과 미전송 입력 구별, 준비 화면과 로그인·권한·신뢰 화면 구별, 과거 프롬프트 오탐 방지, 동일 예약 중복 방지, 각 요청 30초 만료, 한 번 삽입, 전송 실패 시 자동 재전송 금지.
- 취소·경합: 첫 탭 이동·종료·세션 교체, 프로젝트 종료, 기능 비활성화, 늦게 도착한 감지 이벤트, 저장 실패·선택 무효화에서 전송되지 않음.
- 설정·Keymap: 기본 OFF, 기존 사용자 설정 보존, 충돌 시 연결하지 않음, Keymap 변경·재시작, 자동 연결만 제거, 여러 프로젝트에서 단일 연결 관리.
- 어댑터 계약: 화면 순서와 API 목록 순서가 다른 상황, 프로필 탭 재사용, Enter·줄바꿈 없는 참조 전송. 대역 테스트와 실제 IDE 검증을 구분한다.

JDK 25를 `JAVA_HOME`으로 사용하고 JDK 21을 설치한 환경에서 다음을 통과해야 한다.

```bash
./gradlew test testJava21
./gradlew build verifyPlugin
```

Java 25·21 유틸리티 테스트, Java 21 편집기 fixture 테스트 및 두 IDE의 Plugin Verifier 보고서를 확인한다. 리플렉션으로 연결하는 신형 API는 Plugin Verifier 통과만으로 검증 완료로 간주하지 않는다.

Codex 예시 플러그인은 현재 descriptor상 2025.3 이상을 요구한다. 2024.2에 설치할 수 없는 조합은 비호환 사유와 함께 해당 없음으로 기록하고 강제로 설치하지 않는다. 2024.2에서도 독립 실행한 실제 Codex·Claude CLI는 검증한다. 설치 가능한 공존 조합은 해당 IDE에서 검증하고 불가능한 조합을 통과로 표시하지 않는다.

각 결과에는 실제 IDE·CLI·공존 플러그인 버전, OS·셸·터미널 엔진, 시나리오, 기대·실제 결과와 미해결 제한을 남긴다. 화면 변경에 따른 감지 한계와 검증한 CLI 버전을 사용자 안내에 반영한다. 모든 필수 자동 검증과 적용 가능한 실제 IDE 검증이 완료되어야 기능 구현 완료로 판단한다.
